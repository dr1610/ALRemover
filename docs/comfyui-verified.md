# ComfyUI版の検証記録

検証日：2026-09-14。対象：ALRemover v1.4.0-beta.1。

## 環境と分離範囲

Windows / RTX 5070 12GB、ComfyUI 0.35.0（`40c4fcdf`）、Frontend 1.51.10、Python 3.12.12、Torch 2.14.0+cu130、torchvision 0.29.0+cu130、Transformers 5.17.0、Hugging Face Hub 1.31.0、timm 1.0.29、NumPy 2.5.2、Pillow 12.3.0。

既存のComfyUI本体・Python環境を使い、拡張・入力・出力・ユーザー設定・データベース・モデル保存先・Hugging Faceキャッシュを検証用に分離して起動した。不足していたtimmは検証専用ディレクトリから読み込んだ。OSやComfyUIの仮想環境を新規作成した検証ではない。

起動時には `--base-directory` に加えて **`--database-url` も検証先へ明示する必要があった**。明示しない初回起動ではComfyUIが既存DBをバックアップへ移動する自動移行を行ったため、元DBをバイト単位で一致する状態に復元し、以後は独立したDBで検証した。

## 確認したこと

- 3ノードがComfyUIへ登録され、BEN2が既定であること。
- 空のモデル保存先・空のHugging FaceキャッシュからBEN2を自動取得し、推論が成功すること。重みは380,577,976バイト。初回のワークフロー全体は約20.1秒だった。
- BEN2・ToonOut・順送り・逆送りの4方式で、切り抜き→部分修正→キャラクター／背景の透過PNG保存が成功すること。ToonOutの重みは既存の固定リビジョンのファイルを検証先へコピーし、新規ダウンロードは再検証していない。
- 896×1152の入力で、保存画像のRGBが全画素一致し、人物と背景のアルファの和が入力アルファと一致すること。
- 別の一人画像に半透明・完全透明の領域を加えた入力でも、BEN2→部分修正→保存を実行し、元RGBと入力アルファの分配を確認した。
- Keep/Eraseの実際の増減、修正していない画素の保持、修正無効化で最初の切り抜きへ戻ること。
- 修正の再実行でCutoutノードがComfyUIのキャッシュから再利用され、モデル推論が再実行されないこと。
- 配布ワークフローをブラウザーから読み込み、標準マスクエディターでKeepとEraseを描いて保存し、修正を有効化してPNG出力できること。描画テストでは3,442画素を復元し、3,136画素を消した。標準Save Imageのworkflow・promptメタデータも確認した。
- BEN2の一枚のマスクをNeoの既存結果と比較し、最大アルファ差は1/255。Torch等の環境は異なる。全環境での完全一致を保証するものではない。
- 単体テスト15件：切り抜き・レイヤー操作9件と、ComfyUIの透過方向・既存アルファ・部分修正・バッチ・サイズ検証6件。人物別機能とそのテストは削除した。
- 共有エンジンの変更後、Neoの分離した検証環境でもBEN2を確認した。その後、Neoの専用タブを削除し、Script経由の操作に統一した。
- CUDA搭載機でCPUを明示したBEN2エンジン単体の推論も確認した。上流がCUDAの有無だけで半精度を選ぶ箇所は、CPU等では上流のfloat32前処理を使う対応を追加した。この追加確認はNeo側のPython/Torch環境で実施し、896×1152のマスクを約15.3秒で得た。

モデルを使わない単体テストはGPUでの正解率を測るものではない。上記の推論確認にも正解マスクによるIoU評価は含まない。

## 未確認・対象外

- CPUモードで起動したComfyUI全体の操作、MPS・ROCm・DirectML等での実推論、別GPU・別OS。
- ComfyUIの世代を広くまたいだ互換性、Registry／Manager検索一覧からの導入。
- 生成モデルを同時に載せた状態でのVRAM限界、実際のtxt2img／img2img生成との連結。
- 人物ごとの分離・検出枠編集・隠れた背景の生成補完。

標準の画像・マスク・表示・保存ノードを利用する構成であり、NeoのGradio画面をComfyUIへ埋め込む実装ではない。使い方は [ComfyUIガイド](comfyui.md)、再現用テストは [verify_comfyui.py](../tests/verify_comfyui.py)。
